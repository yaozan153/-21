# -21# -# C题 Q3 AlphaEvolve 多对话交接包

## 0. 使用方法

本文件用于把问题三并行交给多个全新对话。操作时：

1. 向每个候选对话发送“共同上下文”全文；
2. 再附上对应的“路线角色指令”；
3. 同时提供原题 `C题.pdf`、附件1至附件3和 `附件/附件5/result3.xlsx` 模板；
4. 候选对话必须独立完成数据读取、建模、代码、数值实验、结果文件和交接报告；
5. 全部候选完成后，把各方案产物连同“最终进化裁判提示词”交给新的裁判对话。

这相当于 AlphaEvolve 的一轮：建立候选种群 → 独立求解和实验 → 统一评估 → 选择与重组 → 再验证进化方案。

## 3. 已完成的 Q1 基线

问题一是确定性储能经济调度：已知单日电价、负荷预测和光伏预测，以 10 分钟为一个时段，建立连续线性规划。

共同物理参数：

- 每天 144 个时段，`Δt=1/6 h`；功率数据乘 `1/6` 转为 kWh；
- 储能容量 12000 kWh，SOC 允许区间 `[1200,10800] kWh`；
- 初始和日末储能量均为 6000 kWh；
- 最大充、放电功率均为 5000 kW，对应每时段 833.3333 kWh；
- 主结果暂按充电效率和放电效率分别为 `η_c=η_d=0.9`；题面“充放电效率90%”存在口径歧义，后续应做往返效率敏感性。

核心约束：

`g_t + P_t - w_t + d_t = L_t + c_t`

`e_t = e_(t-1) + η_c c_t - d_t/η_d`

求解采用三阶段字典序 LP：总购电费 → 弃光 → 充放电吞吐量，以减少退化解和无意义同时充放电。

## 4. 已完成的 Q2 基线

Q2 的最终主线不是简单向 Q1 增加松弛量，而是：

`确定性储能LP → 历史联合场景 → 风险厌恶两阶段随机规划 → 固定日前计划的滚动MPC执行`。

关键信息结构：

- 每天0:00只能使用目标日前数据制定计划购电 `g_t`；当天实际负荷和光伏只用于事后执行和结算；
- 所有场景共享第一阶段计划购电 `g_t`，满足非预见性；
- 场景揭示后，储能、紧急购电、弃光和计划电量弃置可以补救；
- 紧急购电 `h_ts` 是外部电网真实供电，价格为 `5p_t`，不是允许停电的虚拟松弛；
- 联合抽取完整日负荷与光伏，保留两者相关性和日内连续性；
- 用 CVaR 控制少数场景的尾部紧急购电费用；
- 日内滚动阶段固定 `g_t`，只调整储能、弃光和紧急购电。

Q2 主模型：

`min Σ_t p_t g_t + Σ_s π_s Q_s + λ CVaR_β(Q)`

`Q_s = Σ_t 5p_t h_ts`

`g_t + h_ts + P_ts - w_ts + d_ts = L_ts + c_ts + u_ts`

`e_ts = e_(t-1,s) + η_c c_ts - d_ts/η_d`

默认实现参数：最多8个历史联合场景，`β=0.95`，`λ=0.05`，历史窗口84天，MPC每24个10分钟时段即每4小时滚动一次。默认结果不能写成逐10分钟MPC。

# 二、路线角色指令

将共同上下文与下列某一个角色指令一起发送给对应候选对话。

## A. 激进创新型

你的目标是在严格因果和可运行前提下探索创新上限。优先考虑多阶段风险厌恶随机规划、嵌套/近似 CVaR、预测版本价值、滚动场景树、机会约束、分布鲁棒优化或策略参数化。必须控制维数，说明采用场景树缩减、近似动态规划、滚动时域或分解算法的原因。至少保留一个简单基线，并用真实实验证明复杂模型的增益。若高级模型全年不可行，提交“可运行主模型 + 高级小规模实验”，明确两者边界。

路线目录名：`aggressive`。

重点研究：如何把0:00、6:00、12:00、18:00四个信息节点建成真正的多阶段非预见性结构；是否能定量给出预测更新的期权价值。

## B. 稳健工程型

你的目标是优先保证模型正确、全年稳定、Excel可交付和论文易解释。优先使用线性规划或小规模情景 LP，采用滚动优化实现四个预测节点，尽量复用 Q1/Q2 验证器。先准确实现计划量与调整量结算，再做最少但有说服力的基线和敏感性实验。不得因追求模型名称牺牲运行稳定性。

路线目录名：`conservative`。

重点研究：如何用最少变量准确实现冻结决策、调整增减费用、SOC连续继承和紧急购电；确保334天可复现。

## C. 理论严谨型

你的目标是给出最清晰的多阶段决策理论、结算函数和最优策略结构。优先推导分段线性调整成本、凸性/可行性/有界性、非预见性约束、KKT或对偶价格解释，并讨论1.5倍上调价和50%下调违约价对应的分位数或阈值结构。理论必须由至少一个可运行实现和真实实验支撑，不能只写证明。

路线目录名：`theoretical`。

重点研究：澄清“计划—调整—紧急”三种购电的边际成本关系，解释为什么以及何时值得等待新版预测再调整。

## D. 数据预测型

你的目标是重点挖掘附件3中四个发布时刻的预测误差结构及其经济价值。分析不同提前期、月份、时段和天气形态下的预测偏差，建立校准、残差场景或分位数模型，再把它接入一个透明、可运行的滚动优化器。比较原始预测和校准预测对总费用、紧急购电与调整成本的影响。所有训练严格滚动，禁止未来信息泄漏。

路线目录名：`data_driven`。

重点研究：6:00、12:00、18:00预测相对0:00预测究竟改善了哪些时段；是否存在收益很低、可以省略的更新节点，是否值得增加其他预测时刻。

第二轮不要再次做四个宽泛方案，而应针对第一轮暴露出的1至3个明确瓶颈定向变异，并保持统一评测集。

# 五、推荐的整个工作流

```text
公共事实与Q1/Q2基线
          ↓
 ┌────────┼────────┬────────┐
激进型   稳健型   理论型   数据型
模型+代码+全年实验+结果文件+报告
 └────────┼────────┴────────┘
          ↓
资格审计与统一指标复算
          ↓
选择可行父代 + 提取互补模块
          ↓
最终进化模型重新运行全年
          ↓
result3.xlsx + 论文交接文档
          ↓
针对明确瓶颈决定是否进入第二轮
```

该流程的核心不是让多个对话重复写方案，而是要求它们产生可以被统一复算的候选程序和实验结果。最终裁判只融合已经过数据实验支持且彼此兼容的模块。
